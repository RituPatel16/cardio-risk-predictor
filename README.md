# Vitalis — Cardiovascular Risk Predictor

A full-stack rebuild of your Streamlit prototype: a **FastAPI** backend serving
the logistic regression model from your notebook, and a **React** frontend
themed around an ECG monitor.

```
cardio-app/
├── backend/          FastAPI app + trained model
│   ├── main.py
│   ├── train_model.py
│   ├── cardio_train.csv
│   ├── requirements.txt
│   ├── logistic_model.pkl   (generated by train_model.py)
│   ├── scaler.pkl           (generated by train_model.py)
│   └── metrics.json         (generated by train_model.py)
└── frontend/         React + Vite + Tailwind app
    ├── src/
    ├── package.json
    └── ...
```

## 1. Backend setup

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# Reproduces the notebook pipeline (IQR outlier removal, scaling, training)
# and writes logistic_model.pkl, scaler.pkl, metrics.json
python train_model.py

# Start the API on http://localhost:8000
uvicorn main:app --reload --port 8000
```

Check it's alive: open http://localhost:8000/api/health — should return `{"status":"ok"}`.
Interactive API docs are auto-generated at http://localhost:8000/docs.

## 2. Frontend setup

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open the URL Vite prints (usually http://localhost:5173). The dev server proxies
`/api/*` requests to the backend on port 8000 (see `vite.config.js`), so both
servers need to be running at the same time.

## 3. Build for production (optional)

```bash
cd frontend
npm run build      # outputs static files to frontend/dist
```

Serve `frontend/dist` with any static host, and point it at your deployed
FastAPI backend (update `vite.config.js` proxy or add a full URL in
`src/App.jsx` fetch calls if the API isn't on the same origin).

## 4. Deploy the frontend and API on Vercel

This repository is set up as two Vercel projects so Vercel can build the Vite
site and FastAPI service with their own runtimes. Push the `cardio-app` folder
to a GitHub repository first, then import that same repository twice in Vercel.

### API project

1. During import, set **Root Directory** to `backend`.
2. Leave the framework/build settings on automatic detection. Vercel detects
   FastAPI from `main.py` and installs `requirements.txt`.
3. In **Settings → Environment Variables**, add `FRONTEND_ORIGINS` with your
   frontend's Vercel origin, such as `https://your-site.vercel.app` (no trailing
   slash). For preview deployments, include each allowed origin separated by a
   comma, or temporarily use `*` for a public demo.
4. Deploy. The API should respond at `/api/health`; its interactive docs are at
   `/docs`.

The checked-in `logistic_model.pkl`, `scaler.pkl`, and `metrics.json` are
required at runtime. Keep them in `backend/` and commit them with the project.

### Frontend project

1. Import the same GitHub repository as another Vercel project.
2. Set **Root Directory** to `frontend`. Vercel should detect Vite; use
   `npm run build` and `dist` if it asks for build settings.
3. Add `VITE_API_BASE_URL` with the API project's origin, such as
   `https://your-api.vercel.app` (no trailing slash), then deploy.

Redeploy the frontend whenever this environment variable changes. For local
development, leave it unset: Vite uses its existing `/api` proxy to reach
`localhost:8000`.

## What changed vs. the notebook / Streamlit version

- **Same model & features**: logistic regression on age, gender, height,
  weight, systolic/diastolic BP, cholesterol, glucose, smoking, alcohol,
  activity — trained exactly as in your notebook (IQR outlier removal on
  age/height/weight/ap_hi/ap_lo, then `StandardScaler` + `LogisticRegression`).
- **API layer**: the model now lives behind a FastAPI service instead of being
  loaded directly inside the UI, so any frontend (or another app) can call it.
- **Explainability**: each prediction now returns the top 5 features that
  pushed *that patient's* risk up or down (using their standardized value ×
  coefficient), plus BMI and pulse pressure, which the original app computed
  implicitly or not at all.
- **Model diagnostics view**: accuracy, AUC, confusion matrix, ROC curve and
  global feature importance are exposed via `/api/model-info` and shown in the
  UI, so the "trust the model" story isn't just a single accuracy number in a
  notebook cell.
- **New frontend**: a 4-step wizard (styled as ECG monitor "leads") replacing
  the single long Streamlit form, with an animated risk gauge and heartbeat
  motif instead of a plain progress bar.

## Notes

- `cardio_train.csv` is included in `backend/` so `train_model.py` runs out of
  the box. If you retrain on different data, keep the same column names and
  order (`id;age;gender;height;weight;ap_hi;ap_lo;cholesterol;gluc;smoke;alco;active;cardio`,
  semicolon-separated).
- This is an academic project. The prediction is a statistical estimate, not a
  medical diagnosis — the UI says so, and it's worth keeping that disclaimer
  if you present this.
